## 1. 一句话

**一款关于「计划」与「意外」的公路旅行模拟器：你在全国路网上选一条线，带着有限的载重、燃料和体力出发，然后接受地理与季节给你的一切安排。**

不是竞速游戏，不是生存游戏，不是驾驶模拟器。

## 2. 体验目标（玩家应该记住什么）

- 出发前那半小时的**准备**，比路上任何一次超车都重要。
- 在某个县城加油站，因为差 3 升油而改了整条路线。
- 从下雨的盆地骑到高原的雪线，一格一格看着气温表掉下去。
- 到地方了，熄火，手还在抖。

## 3. 三个支柱

| 支柱 | 含义 | 具体表现 |
| --- | --- | --- |
| **地理是真的** | 距离、海拔、气候、补给密度都按真实地理走 | 全国路网图、纬度/海拔/季节驱动的气温与天气、真实地名与里程 |
| **准备是有意义的** | 车、装备、载重、路线共同决定你能不能到 | 选车、改装、装行李、改路线、算油量 |
| **路上的小决定** | 每个决定都很小，但累积成完全不同的一趟 | 要不要再骑 80 公里、要不要加满、要不要停下来睡一觉 |

## 4. 明确不做（防止功能爆炸）

- ❌ 真实物理驾驶（不做压弯角度、轮胎滑移率、前叉行程）
- ❌ 连续地形 / 3D 世界 / 开放世界漫游
- ❌ 联网、多人、排行
- ❌ 全程第一人称
- ❌ 建模级地图（不追求街景、不追求精确到路口）

## 5. 系统总览

```
计划层 ─────────────────────────────┐
 选出发点 / 选车 / 选装备 / 定路线     │
                                    ↓
地图层（全国路网）→ 选择下一段行程 ──┐
                                    ↓
路段层（骑行）→ 实时操作 + 事件卡片 ──┤
                                    ↓
休整层（城镇/营地）→ 加油吃饭睡保养 ──┘
                    ↓
              日结算 → 下一天
```

三层界面，三层时间尺度。**这是整个方案的骨架。**

## 6. 地图与路网模型

### 6.1 抽象层级：节点-边（Node / Edge）

不用连续地形，用一张**手工维护的骨架路网**：

```json
{
  "nodes": [
    {"id":"cd", "name":"成都", "type":"city", "lat":30.66, "lon":104.06, "alt":500,
     "svc":{"fuel":3,"stay":3,"repair":3,"food":3,"medic":2}},
    {"id":"zdk","name":"折多山垭口","type":"pass","lat":30.08,"lon":101.79,"alt":4298,
     "svc":{"fuel":0,"stay":0,"repair":0,"food":1,"medic":0}}
  ],
  "edges": [
    {"a":"km","b":"zdk","km":28,"road":"G318","class":"national",
     "surface":"asphalt","toll":false,"motoAllowed":true,"minTurns":12,
     "kits":[0,1,2,3]}
  ]
}
```

- `svc` = 各类服务的**等级 0–3**，不是布尔值。等级决定能做什么：0 级修车铺补不了胎，2 级能换机油，3 级才有原厂配件。
- `class` = 高速 / 国道 / 省道 / 县道 / 土路 / 无路，直接决定速度上限与油耗。
- `kits` = 该边每 10km 的「随机事件密度权重」，手调，让川藏线比 G6 高速危险得多。
- `minTurns` = 弯道数，影响体力与精神消耗，也用来生成「压弯」小玩法。

### 6.2 三个缩放层

| 层级 | 内容 | 玩家做什么 |
| --- | --- | --- |
| **全国层** | 省界、主要国道、城市点、你当前位置、已走路线 | 规划路线、改线、看天气/季节、算里程 |
| **区域层** | 当前省份 / 周边 300km 的路网细化、补给点、海拔色带 | 决定今天骑到哪、明天怎么走 |
| **路段层** | 2D 卷轴（沿用现有侧视图），实际骑行 | 油门/刹车/避让 + 事件卡片 |

三层之间用动画转场，不是切场景，是**镜头推近**。

### 6.3 全国路网的成本控制

这是最大的工作量风险。务实做法：

1. **只做骨架**：约 30 条主要国道 + 10 条纵线，合计 **250–400 个节点**，能连通全国主要摩旅路线（318、219、109、214、312、227、331…）。
2. **不追求完整县道**：玩家只能在骨架路上走；小路用「区域层随机生成路段」代替。
3. **坐标来源**：城市经纬度查表（公开常识数据），用等距圆柱投影画到 canvas 即可，不需要 GIS 库。
4. **省界**：一份简化 GeoJSON（几千点级别），静态资源，一次性。

> 结论：**MVP 阶段只做一条线（318），路网结构一次设计到位，数据分批填。**

## 7. 时间、距离与速度（本版重写）

### 7.1 三条铁律

1. **世界按真实物理运转**：60km/h 骑 3 小时就是 180km，油耗用 L/100km，体力按小时掉。所有数值都是真实单位，不搞「1 公里 = 1 格」的抽象。
2. **玩家看到的时间 ≠ 世界时间**：用可变倍速压缩观看时长。
3. **倍速不改变任何结算**：油耗、体力、疲劳全部按「游戏时间」计算。所以加速是**免费的**——它唯一的代价是「你错过了沿途可以停下来的东西」。

这三条同时解决了两个问题：既不用让玩家真的骑 3 小时，又不让数值失真。

### 7.2 倍率表

| 场景 | 倍率 K | 现实 1 分钟 = | 60km/h 时，现实 1 分钟前进 |
| --- | --- | --- | --- |
| 地图 / 规划 / 清单 | 暂停 | — | 0 |
| 观景巡航 | 60× | 1 游戏小时 | 60 km |
| 赶路巡航 | 300× | 5 游戏小时 | 300 km |
| 空旷直路（高速 / 戈壁） | 600× | 10 游戏小时 | 600 km |
| 停车休整 | 按行动点结算 | — | 0 |
| 睡眠 | 直接跳到次日 06:00 | — | — |

倍率由玩家随时切换（默认 60×，按键升档）。**升档不会让你更省油，只会让你更少停下来。**

### 7.3 换算公式

```
游戏秒  += 现实秒 × K
里程 km += 速度(km/h) × 游戏秒 ÷ 3600
燃油 L  -= 油耗(L/100km) × 里程 ÷ 100
体力    -= 每秒消耗率 × 游戏秒
```

### 7.4 一天的账

| 时段 | 内容 | 游戏时长 |
| --- | --- | --- |
| 06:00–07:00 | 起床、收帐篷、吃早饭 | 1 h |
| 07:00–12:00 | 骑行（2–3 段） | 5 h |
| 12:00–13:30 | 午饭 + 休息 + 加油 | 1.5 h |
| 13:30–18:30 | 骑行（2–3 段） | 5 h |
| 18:30–20:00 | 找住处、洗澡、吃晚饭、修车 | 1.5 h |
| 20:00–22:00 | 清单时间（3 个行动点） | 2 h |
| 22:00–06:00 | 睡眠 | 8 h |

- 一天约 **10 小时**骑行，平均 **45 km/h**（含烂路、垭口、等落石）→ **350–450 km/天**。这是真实长途摩旅的强度，不是游戏化的虚数。
- 观景巡航下一天 ≈ 8–10 现实分钟；赶路下 ≈ 2 分钟。
- **318 全程约 2100km ≈ 5–6 天**；**川进青出约 8 天 ≈ 45–60 现实分钟**；**1 万公里大环线约 25 天**（分多次存档玩）。

### 7.5 速度是怎么算出来的

玩家设的是「巡航意图」，实际速度取最小值：

```
实际速度 = min(车极速, 巡航意图, 环境上限)
环境上限 = 基准 90
         × 路面系数 × 弯道系数 × 天气系数
         × 夜色系数 × 海拔系数 × 载重系数 × 车况系数
```

| 路面 | 系数 | 典型巡航 |
| --- | --- | --- |
| 高速 | 1.15 | 105 |
| 国道 | 1.00 | 90 |
| 省道 | 0.80 | 70 |
| 县道 | 0.65 | 58 |
| 土路 / 碎石 | 0.40 | 36 |
| 涉水 / 烂泥 | 0.20 | 18 |

| 条件 | 系数 |
| --- | --- |
| 弯道密集 | 0.70–0.90 |
| 雨 | 0.75 |
| 雾 | 0.60 |
| 冰雪 / 结冰桥面 | 0.45 |
| 夜间 | 0.70 |
| 海拔 > 4000m（化油器车型） | 0.85 |
| 超载 20% 以上 | 0.90 |
| 车况差 / 轮胎磨损 | 0.85 |

### 7.6 油耗与体力

```
油耗(L/100km) = 基础油耗 × (实际速度 ÷ 经济速度)^1.4      经济速度 ≈ 65 km/h
体力(/h)      = 6 ÷ 舒适度 × 速度因子 × 环境因子
速度因子 = 1 + (速度 − 65) ÷ 200
环境因子 = 雨 1.3 / 夜 1.25 / 低温 1.2 / 烂路 1.5 / 高原 1.15
```

参考值：ADV（20L 油箱、国道 80km/h、4.5L/100km）→ 续航约 380km；
踏板（5L 油箱、60km/h、2.2L/100km）→ 续航约 200km。
**这两个数字决定了整条路线上「加油焦虑」的密度，也决定了副油箱值不值 30 分钟去装。**

### 7.7 事件与打卡的触发方式

**按里程触发，不按时间触发。**

- 每条边在生成时就把事件点钉死在里程上（例如 34km 处有个加油站、87km 处塌方）。
- 无论 60× 还是 600×，走到那个点都会触发。
- 差别在于：**赶路档位下事件以「一晃而过」处理**——只闪一条通知，不停车、不弹卡；景点记为「路过未停」，进日志。
- 于是加速的代价不是资源，而是**记忆**。这比扣钱优雅得多。

## 8. 车辆系统

### 8.1 属性（够用就行，不追求拟真）

| 属性 | 作用 |
| --- | --- |
| 极速 / 巡航速度 | 单位时间能走多远 |
| 油箱容积、油耗（L/100km） | 续航，决定补给焦虑 |
| 舒适度 | 体力/屁股痛衰减速度 |
| 通过性（离地间隙、胎型） | 能不能走烂路、土路、涉水 |
| 载重上限 | 行李重量的硬约束 |
| 可靠度 | 故障事件概率 |
| 座高 / 整备质量 | 倒车后能不能自己扶起来（真实痛点） |
| 储物点 | 边箱 / 尾箱 / 绑扎点，决定能装什么 |

### 8.2 车型（首批）

踏板（省心、油箱小、不能越野）· 街车（中庸）· ADV（能越野、能载、贵）· 巡航（舒适、通过性差）·
越野/林道（能走土路、极速低、油耗高）· 老式 125（便宜、可靠度低但哪都能修）。

**关键设计：每辆车都应该有至少一个「明显的缺陷」**，让选择产生后果。

### 8.3 改装与配件

副油箱、护杠、大风挡、加热手把、外挂灯、胎压监测、GPS 支架、行车记录仪。
改装受**载重**与**预算**双重约束。

## 9. 行李与载重

**这是本作的核心玩法之一**，因为它把「准备」变成可玩的算术。

- 每件物品：重量（kg）、体积（L）、功能标签、耐久。
- 载重上限之外 → 操控变差（事件判定 +惩罚）、油耗上升、摔车损失更重。
- 体积上限之外 → 装不下（必须取舍）。

物品示例：

| 类别 | 物品 | 效果 |
| --- | --- | --- |
| 防护 | 雨衣、防寒内胆、护具、雨靴 | 抗雨/抗寒，缺失时体力与心情双惩罚 |
| 露营 | 帐篷、睡袋（温标）、气垫、炉头 | 无住宿时保底恢复，但占体积 |
| 维修 | 补胎工具、气泵、链条油、随车工具、备用内胎 | 故障时自主解决 vs 等救援 |
| 能源 | 副油箱、充电宝、备用电瓶 | 延长续航 / 维持设备 |
| 记录 | 相机、运动相机、三脚架 | 照片分与回忆 |
| 生活 | 保温杯、防晒、常用药、现金 | 小块但决定体验 |

## 10. 地理与季节 → 天气与路况

### 10.1 气温模型（简化，可读即可）

```
temp = 基础温度(纬度, 月份) − 海拔 * 0.0065 − 时段修正 + 天气修正
```

- 再叠加区域气候修正：华南湿热、西北干冷、川西多雨、青藏大风。
- 目标是让玩家看到「同一件夹克在成都够用，在折多山不够用」。

### 10.2 降水 / 极端天气

| 区域 | 季节 | 主要威胁 |
| --- | --- | --- |
| 华南 | 4–6 月前汛期、7–9 月台风 | 暴雨、道路积水、航班式封路 |
| 西南 | 6–9 月雨季 | 塌方、泥石流、落石 |
| 西北 | 冬季 | 冰雪路面、夜间极寒 |
| 青藏 | 全年 | 大风、暴雪、紫外线、缺氧 |
| 华北 | 冬季 | 雾霾/大雾、严寒 |

极端天气的用途：**封路**（必须等或绕行）——这是让玩家与地图互动的最强手段。

### 10.3 高原反应

海拔 3000m 以上按海拔与上升速度累积「高原反应」值：
头痛 → 无力 → 必须下撤或停留适应。这是真实摩旅的死亡项之一，也天然制造节奏。

## 11. 骑行动作系统（本作最关键的一块）

真实摩旅动作非常多，如果全部做成实时操作，游戏会变成街机。
**因此把动作分为三层，各自用不同交互形式承载：**

### A. 实时操作层（路段视图内，占比約 30%）

| 动作 | 交互 | 后果 |
| --- | --- | --- |
| 给油 / 松油 / 刹车 | ↑ ↓ | 速度、油耗 |
| 避让坑洼 / 碎石 | 左右微调 | 撞上 → 车损、摔车判定 |
| 压弯（弯道降速） | 弯道提示时降速 | 超速过弯 → 摔车 |
| 夜间开灯 / 判断是否继续 | 开灯键 | 视野、事件概率 |
| 推车 | 油尽时自动 | 极慢，耗体力 |

### B. 事件卡层（路上，占比約 50%）

沿用现有事件结构，但扩展为**结构化**的事件：每张卡有 `标签 / 描述 / 2–3 个选项 / 明确代价`。
覆盖：加油站、小馆、客栈、修车铺、塌方、查车、被狗追、老骑友、风景点、边检。

**原则：每张卡的两个选项都必须是「有代价的合理选择」**，不做「明显最优解」。

### C. 清单层（休整界面，占比約 20%）

到达城镇/营地后，进入「今晚你做什么」的清单，时间有限，只能做几件：

- 加油 / 找住处 / 洗澡洗衣 / 吃热的
- 补胎 / 调链条 / 紧螺丝 / 换机油（需要 repair 等级够）
- 充电 / 备份照片 / 洗装备 / 晾雨衣
- 拉伸、泡脚、早点睡
- 看明天天气、改路线

清单的乐趣是**时间预算**：只有 3 个小时，你要 6 件事里选 3 件。

### D. 状态层（被动触发的强制动作）

- 体力 < 20 → 必须停下，否则判定摔车
- 高原反应 → 必须停留适应或下撤
- 连续骑行 > 6 小时 → 注意力衰减，事件判定变差
- 失温/中暑 → 强制结束当天

> 这套分层的好处：**操作只负责氛围，决策负责玩法。**

## 12. 景点、打卡点与「值得停下来」（新增 · 重点）

> 「摩旅的一半是路，另一半是你停下来的地方。」
> 景点系统不是装饰，它是**里程之外的第二条目标线**，也是季节系统唯一真正的出口。

### 12.1 三级 POI

| 级别 | 说明 | 在地图上的表现 |
| --- | --- | --- |
| 国家级 | 布达拉宫、纳木错、喀纳斯、敦煌 | 全国层显示名字与图标，错过进「遗憾清单」 |
| 地区级 | 婺源、恩施大峡谷、赛里木湖 | 区域层可见 |
| 路边级 | 观景台、经幡、老桥、废弃道班 | 只在路段视图里出现，停下来才发现 |

### 12.2 数据结构

```json
{
  "id": "ranwu-lake",
  "name": "然乌湖",
  "level": "national",
  "at": "node:ranwu",
  "detourKm": 0,
  "visitMin": 90,
  "ticket": 0,
  "best": { "months": [3,4,5,9,10], "time": "dawn" },
  "tags": ["lake", "snow", "photo"],
  "score": 5
}
```

- `detourKm` 是整个系统的灵魂：**要不要绕**。绕 40km = +1 小时 + 2L 油 + 8 点体力。
- `best` 是「最佳打卡条件」：同一个湖，晴天清晨是 5 分图，阴雨中午只有 2 分图。
- POI 与路网节点共用一套坐标，直接挂在 `node` 或 `edge` 上。

### 12.3 打卡是三个动作，不是一个判定

1. **绕过去** —— 消耗里程 / 油 / 体力
2. **停下来** —— 消耗时间（`visitMin`）
3. **按下快门** —— 消耗一点体力，产出一张有评分的照片

```
照片分 = 基础分 × 季节系数 × 时段系数 × 天气系数 × 装备系数
装备系数：手机 1.0 / 微单 1.2 / 长焦 1.35 / 三脚架额外 +0.1
```

**这给「在这儿多住一晚，等明早的光」提供了真实动机**，也让季节第一次真正影响玩法，而不只是换个颜色。

## 13. 资源与状态

| 资源 | 范围 | 归零后果 |
| --- | --- | --- |
| 时间 | 天/小时 | 进度落后、季节变化、封路 |
| 体力 | 0–100 | 强制休息，掉一天 |
| 精神（心情） | 0–100 | 低于阈值触发「想回家」事件；高心情解锁额外事件 |
| 油量 | 升 | 推车/呼救 |
| 钱 | 元 | 只能露营、只能吃泡面 |
| 装备耐久 | 每件独立 | 雨衣破了不再防水，睡袋湿了不保温 |

**精神值**是我建议新增的：摩旅最真实的敌人不是路，是「骑烦了」。

## 14. 循环

### 单日循环
```
早晨（看天气 / 定今日目标）
  → 骑行 1~4 段（实时 + 事件卡）
  → 黄昏（决定再骑还是找地方）
  → 休整清单（时间有限，做不完）
  → 日结算
```

### 一局的循环
```
计划（选起点/车/装备/路线）→ 出发 → 若干天 → 抵达 or 中断
```
建议一局长 30–90 分钟，中途可存档。

## 15. 失败与叙事

**不设死亡、不设 Game Over。** 三种结束：

1. **抵达**：完成路线。
2. **中断**：车报废 / 钱花光 / 身体撑不住 → 提前结束，结算为「未完成」。可以在下一个城镇重开续接。
3. **改主意**：玩家主动结束（很多人真的会中途回家）。

结算看的是：里程、日子、花销、照片、路上遇到的人，而不是分数。

## 16. 表现层

- **全国层**：等距投影的简化地图，海拔用色带，路线用高亮线条，像一张摊开的纸质地图。
- **区域层**：省界 + 路网 + 补给点图标 + 未来 48 小时天气带。
- **路段层**：沿用现有 2D 卷轴（侧视），保留天气/昼夜/视差；这是最省成本且最有氛围的方案。
- **美术方向**：低饱和、纸质地图质感、手写体标注，夜晚暖光。

## 19. 定案与剩余问题

### 已定案（v0.2）

1. **地图**：全国骨架路网，分批填数据。
2. **操作**：轻操作（油门 / 避让 / 过弯降速），不追求驾驶手感。
3. **失败**：车坏了必须找修车铺或等救援，可能中断行程；**没有 Game Over**。
4. **精神值**：做。
5. **钱**：做（住宿 / 加油 / 修理 / 门票）。价格用**区域均价**，不追求精确到每家店。
6. **一局时长**：30–90 分钟一个目标，可存档续接；大环线分多次玩。
7. **真实地名与真实里程**：要，这是最大的差异化。
8. **时间**：世界按真实物理算，玩家侧用可变倍率（§7）。
9. **景点/打卡**：必须有，约 100 个起步（§12）。

### 还需要你定的 3 个小事

1. **能不能中途放弃行程？**（把车寄回去、坐火车回家）——我倾向：能，这是一种很真实的选择。
2. **相册要做到什么程度？** 只做结算展示，还是做一个能翻看/按地点整理/导出图片的相册界面？
3. **事故的严重上限**：最坏是「车报废，必须搭车离开，行程中断」够不够狠？还是要能受伤住院？
